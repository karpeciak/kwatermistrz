## Co zmienia ten pull request

Po zatwierdzeniu wniosku osoba akceptująca porównuje i wybiera przejazdy tam
i z powrotem. Rekomendowana para uwzględnia preferowany transport i kolejność
godzin: powrót o 17:00 nie jest rekomendowany z dojazdem o 18:30 tego samego dnia.
Odstępstwo wymaga uzasadnienia, a zmiana transportu dodatkowo jawnej zgody.

- API oraz agent sprawdzają uprawnienia, terminy, kierunki i ponowienie komunikatu.
  Oba odcinki zapisują się razem z audytem decyzji człowieka; wynik trafia do Koordynatora.
- Lista Podróże pokazuje własne oraz akceptowane wnioski. Nieznana trasa umożliwia
  dodanie sprawdzonych ofert ze źródłem lub przekazanie do uzgodnienia.
- Ekran ma jeden główny komunikat, karty obu kierunków i sumę kosztów. Szczegóły,
  alternatywy i historia są rozwijane. Walidacja serwera działa niezależnie od JavaScript.
- Podpisane sesje demo wygasają; zalogowane zapisy formularzy /app wymagają CSRF,
  także autozapis, podsumowanie, decyzje, rozliczenia i zakwaterowanie. Token działa
  w natywnych formularzach oraz HTMX. Wygasła sesja HTMX przekierowuje całą stronę
  do logowania. Logowanie pozostaje demonstracyjne, bez hasła.
- Słownik transportu jest wspólny dla formularzy i API. Wyszukiwarka miejscowości
  obsługuje Photon/OpenStreetMap z cache, limitem na proces i rozróżnieniem błędu DNS.
- Scalono origin/main 04c561b, zachowując podsumowanie i wersje robocze wniosku,
  kontrolę budżetu, statusy, rozliczenia i ekrany organizacji wyjazdu.
- Ekran delegowanego /przejazd i ekran osoby akceptującej używają wspólnego
  WyborPodrozy. Tożsamość pochodzi z sesji, oba POST transportu sprawdzają CSRF,
  agent dopuszcza delegowanego lub osobę akceptującą. Dodawanie ofert nadal jest
  zastrzeżone dla osoby akceptującej. Rezerwacja noclegu z main została zachowana.
- Lokalny launcher uruchamia wszystkich istniejących agentów, SQLite i broker
  w pamięci. Nie tworzy automatycznie wniosków ani podróży demo.

Wspólne pliki zmieniono osobno: bb2b731 — Koordynator wymaga obu kierunków;
0f669b6 — messaging, komunikat dodania oferty. Własna część nie dodaje migracji;
main zawiera migrację 0003 nowego pola budzet_wydatkowany, dołączoną wraz z modelem.

## Dane i ograniczenia

- Żołnierze i PRZ-01…03 pochodzą z repozytorium. Do testowania obu kierunków dodano
  fikcyjne oferty powrotne w seed.py, jawnie oznaczone jako przykładowe. Nie są rezerwacjami.
- Brak pobierania rzeczywistych rozkładów, cen i dostępności pojazdów. Manualne
  oferty wymagają źródła, a dostępność pojazdu potwierdza jednostka.
- Żywy Photon nie jest potwierdzony (ostatnio błąd DNS). PHOTON_URL umożliwia własną
  instancję; przy większym ruchu potrzebny jest wspólny limit lub własna usługa.
- Ustawić wspólny SESSION_SECRET dla replik i restartów. Ten krok obejmuje formularze
  /app; nie zmienia modelu uwierzytelniania pozostałych API JSON zespołu.
  Model nie zawiera godziny zakończenia zadania.
