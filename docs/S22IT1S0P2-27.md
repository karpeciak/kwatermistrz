# S22IT1S0P2-27 / S22IT1S0P2-57

Implementacja wyboru podróży obejmuje przygotowanie propozycji tam i z powrotem,
porównanie kryteriów, rekomendację regułową, wybór obu przejazdów i odrzucenie wszystkich.
Decyzję podejmuje osoba wskazana jako zatwierdzająca delegację. Delegowany ma podgląd.

## Przepływ

1. Koordynator wysyła `zadanie.transport` po zatwierdzeniu delegacji.
2. Agent zapisuje propozycje z tabeli `Polaczenie`. Rekomendacja kosztowa wymaga
   zatwierdzenia przez człowieka i trafia do audytu.
3. We wniosku pojawia się odnośnik „Porównaj warianty podróży / zobacz wybór”.
4. Osoba zatwierdzająca wybiera kryterium i po jednym przejeździe w obu kierunkach.
   Odstępstwo i odrzucenie wszystkich wymagają uzasadnienia.
5. API publikuje `wybor.transport` (202 oznacza przyjęcie do obsługi).
6. Agent ponownie sprawdza uprawnienia i reguły, blokuje wiersz delegacji, zapisuje oba
   odcinki w jednej transakcji i wysyła `wynik.transport`. Ponowione zadanie nie tworzy
   duplikatów, ponowiona ta sama decyzja nie zmienia wyboru.
7. Koordynator wymaga wybranego przejazdu w obu kierunkach przed zakończeniem organizacji.

## API i sesje

- `GET /delegacje/{id}/warianty-podrozy?kryterium=standardowe|koszt|czas|bezpieczenstwo|punktualnosc`
- `POST /delegacje/{id}/wybor-podrozy`: `id_tam`, `id_powrot`, `kryterium`, `uzasadnienie`.
  Alternatywnie `odrzuc_wszystkie: true` i uzasadnienie, bez identyfikatorów.
- Sesja powstaje przez istniejące logowanie demo `/app/logowanie`.
  Zapis wymaga `X-CSRF-Token` z formularza `/app/wnioski/{id}/podroz`.
- Cookie jest podpisane HMAC, ważne 8 godzin, HttpOnly, SameSite=Lax, Secure na HTTPS.
  Dowolny surowy identyfikator żołnierza nie jest już poprawnym cookie.
- Wylogowanie jest formularzem POST z tokenem CSRF. Podpis i CSRF nie zastępują
  docelowego uwierzytelniania: w trybie demo nadal można wybrać osobę bez hasła.
- `SESSION_SECRET` należy ustawić jako wspólny losowy sekret w konfiguracji wdrożenia.
  Bez niego używany jest klucz procesu: restart wylogowuje użytkowników, a wiele replik
  nie współdzieli sesji. Nie commitować rzeczywistego sekretu.

## Ograniczenia danych MVP

- Źródłem jest lokalna tabela połączeń, a nie integracja z przewoźnikiem. Kursy powrotne
  w seedzie są oznaczone jako przykładowe. Zapis wyboru nie rezerwuje biletu.
- Termin przyjazdu uwzględnia datę i czas trwania, w tym podróże przez północ.
- Brak godziny rozpoczęcia jest jawnie pokazywany użytkownikowi.
- Różnica czasu ponad 60 minut powoduje ostrzeżenie i sugestię zmiany kryterium.
  To próg prezentacji MVP, wymagający uzgodnienia z PO; nie jest przepisem wojskowym.
- Model nie zawiera godziny zakończenia zajęć: osoba zatwierdzająca musi sprawdzić
  godzinę powrotu. System odrzuca powrót przed dotarciem i rozpoczęciem zajęć.
- Brak odpowiedniego połączenia nie powoduje wymyślenia oferty ani automatycznej zgody.
  Odrzucenie propozycji zapisuje stan „do uzgodnienia” i powiadomienie.
- Nie zmieniono modeli ani schematu bazy. Migracja nie jest wymagana.
- CSRF w tej zmianie obejmuje wybór podróży i wylogowanie; istniejące formularze innych
  obszarów wymagają osobnego rozszerzenia ochrony.
